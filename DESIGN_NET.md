# DESIGN_NET — токенный пайплайн HU+ (заморожено как дизайн v1, до реализации HUNL-toy)

Отвечает на архитектурные вопросы до кода. Критика — сюда; изменения — ревизией.

## 0. «Масштаб инфосетов» — что это и при чём тут бакеты

Инфосет = уникальная с точки зрения игрока ситуация (его карты + борд + история действий).
Kuhn: 12. Leduc (наш, канонизированный): 288. Push-fold: 338. Полный HUNL: **≥ 10^13** —
табличные методы (CFR/DCFR-семейство) туда не помещаются физически; бакетизация карт
(кластеризация по эквити, как у старых лимитных ботов) — один способ сжать, мы его
**не используем**: сжатие делает канонизация (S4 схлопывает перестановки мастей) +
нейросеть, обобщающая по классам ситуаций. Бакеты — fallback, если compute упрётся
в стену (решение отложено до данных).

## 1. Вход: поток событий (токены), append-only

Наблюдение = последовательность событий раздачи от лица игрока (player-centric, SPEC 1):

```
[MY_CARD_1, MY_CARD_2, (STREET_SEPARATOR, BOARD_CARD)*, (ACTION | BET_TOKEN)*, <READOUT>]
```

- **Карты**: токен = (ранг 13 × каноническая масть 4) из S4-канонизатора. Масти
  захвачены рукой (hand-locked) → токены стабильны между улицами → KV-кэш append-only
  (гарантия доказана тестом префикс-стабильности).
- **Действия**: фолд/чек/колл — типовые токены; бет/рейз — токен типа + **two-hot
  (32 узла)** вектор размера ставки, линейно проецируемый в d_model и ДОБАВЛЯЕМЫЙ к
  эмбеддингу типа. Дискретизация входа НЕ квантует: кусочно-линейная интерполяция.
- **Разделители улиц** — собственные токены (позиционная структура очевидна модели).

## 2. Эмбеддинги и позиция

`x_l = Emb(token_l) + PosEmb(l) + W_proj · twohot_l`

- Эмбеддинги обучаемые; позиционный эмбеддинг — обучаемый, аддитивный, длина ≤ 64
  (HUNL: 2+5 карт + ~15-25 действий с разделителями). Внимание перестановочно-инвариантно,
  поэтому позиция обязательна. Альтернатива (relative/ALiBi) — абляция при HUNL-toy.
- Слои: causal self-attention (токен видит только прошлое), pre-norm, d_model=128,
  4 головы, 2 слоя, FF 256 — стартовая точка; абляции ширины/глубины по данным.

## 3. Предикшн — по сетке действий, НЕ по бакетам карт

На решении читаем hidden-состояние ПОСЛЕДНЕГО реального токена → две головы
(сети раздельные, decoupled по SPEC 5.6):
- policy → **K=12 логитов** сетки действий из SPEC (fold .. all-in), маска легальных,
  softmax только по легальным;
- value → скаляр V(I).

Выходная «дискретность» — это сетка ДЕЙСТВИЙ (сайзинги), вход ставок непрерывен
(two-hot). Никаких карточных бакетов на выходе.

## 4. Бэкспроп

Стандартный для трансформера: весь путь токен→логиты дифференцируем; обучаем на тех же
[T, B]-батчах игроко-центричных подтраекторий (SPEC 5): каждая строка (t, b) = один
инфосет = один префикс токенов; паддинг — маской. Движок (V-trace, NeuRD, якоря) НЕ
меняется: ему нужны только logits [T,B,K] и V [T,B]. `TrajectoryBatch` расширяется
полями `obs_tokens [T,B,L]`, `obs_pad [T,B,L]`, `bet_sensor [T,B,L,32]`.

## 5. «Токен-резюм, копящий суть»

Отдельного резервного токена НЕ нужно: causal attention на позиции считывания — это и
есть обучаемое взвешенное резюме всего прошлого; append-only KV-кэш — его вычислительная
форма (инференс инкрементальный). Явный [SUM]-токен — кандидат абляции при HUNL-toy
(зарегистрируем сравнение до запуска, как с оптимизмом).

## 6. Инференс и append-only

Обучение пересчитывает префиксы целиком (нормально на toy-масштабе). Семантика
append-only = **инвариант**: выход на префиксе не меняется при дописывании будущих
токенов — фиксируется tier A-тестом (эквивалент KV-кэша без его реализации).
Инкрементальный KV-кэш — оптимизация инференса на HUNL-масштабе.

## 7. Сделано / доделать / тестировать

**Сделано:** S4-канонизация (брутфорс-гарантии), слоты two-hot/K=12 в SPEC,
движок с [T,B]-интерфейсом, скелет `nets_transformer.py` + tier A (каузальность,
маски, детерминизм).

**Доделать (по порядку):** определение HUNL-toy + пререгистрация порога → словарь
токенов + obs-пайплайн в адаптере → интеграция за интерфейсом сетей → абляции
([SUM]-токен, глубина/позиционка) → гейт HUNL-toy → полный HUNL env (vec, при
необходимости Rust) → масштаб и аренда.

**Тестировать / куда критика:** (1) полнота словаря — различные инфосеты дают
различные токен-последовательности (информационная полнота); (2) каузальность и
паддинг-маски; (3) two-hot на экстремумах (клэмп за сеткой); (4) стабильность
обучения с LayerNorm против MLP-бейзлайна на HUNL-toy (тот же зонд-протокол).
